## 2. The dropped flags (C1) — the highest-severity finding

`obfuscator/core/pipeline.py::main()` used to build the build arguments
by hand:

```python
build_args = argparse.Namespace(
    source=args.source, native=args.native, cf_token=cf_token, ...
)
generated_files_map = build_project(build_args)
```

`build_project()` reads its options with `getattr(args, 'name', default)`
for about forty names. Any name the copy did not list fell back to its
default — silently. Fourteen of them were reachable from the command
line and had no effect.

The fix is structural, not a patch of the fourteen:

```python
# The parsed namespace IS the build namespace.  It used to be a
# hand-built argparse.Namespace, which silently dropped every field
# the copy forgot -- 14 of them -- and turned those flags into no-ops.
args.cf_token = cf_token          # the only fields this function computes
args.net_url = deployed_url
args._cf_hmac_key = hmac_key
args._ntru_pub = ntru_pub_key
args.gh_token = gh_token
generated_files_map = build_project(args)
```

A new flag cannot be forgotten, because nothing is copied.

### What the fourteen flags actually do now

| Flag | Effect |
|---|---|
| `--hwid` | the HWID string for macro expansion and the HWID-locked fallback |
| `--trial` | the trial period spec, parsed by `obfuscator.macros.parse_trial` |
| `--vm-threshold` | the VM-score verdict threshold baked into the loader |
| `--kod` | arms the loader's kill-on-detect response |
| `--hostguard` | prepends the hostguard snippet |
| `--hwid-lock` | HWID-locks the bytecode fallback blob (needs `--hwid`) |
| `--driver-check` | bakes the kernel-driver gate into the loader |
| `--split-bootstrap` | Shamir (n=3,k=2) threshold key + fragmented decoder |
| `--no-snapshot` | omits the frozen-stdlib snapshot gate |
| `--no-stdlib-audit` | omits the stdlib function-audit gate |
| `--name-gate` | rewrites privileged call sites through a per-build token map |
| `--lowering` | the semantic-lowering families CSV |
| `--rename-internal` | renames proven-internal public methods/attributes |
| `--no-audit-hook-plant` | omits the audit-hook plant detector |

### The guard

`tests/test_cli_flags.py` closes the class:

* `test_main_does_not_rebuild_the_namespace` — `main()` must pass the
  parsed namespace straight to `build_project`. Verified to fail when
  the bug is reintroduced.
* `test_every_build_flag_is_consumed` — every flag the `build`
  subcommand advertises must be read somewhere in the module. This is
  the check that would have caught the original bug.
* `test_every_build_flag_reaches_the_namespace` — no flag may be
  swallowed by the parser.

## 3. The CLI audit

The pipeline CLI's parser was **inside `main()`**, which itself was
inside an `if __name__ == "__main__":` block. It could not be imported,
so it could not be tested, so it could not be audited. It is now
`obfuscator.core.pipeline.build_parser()` at module level, and
`main()` is at module level too.

### 3.1 Flags that were dead, and what happened to them

| Flag | Before | After |
|---|---|---|
| `--hwid`, `--trial`, `--vm-threshold`, `--kod`, `--hostguard`, `--hwid-lock`, `--driver-check`, `--split-bootstrap`, `--no-snapshot`, `--no-stdlib-audit`, `--name-gate`, `--lowering`, `--rename-internal`, `--no-audit-hook-plant` (pipeline CLI) | parsed, dropped | **wired** (§2) |
| the same 11 in `scripts/build.py` | parsed, logged as if applied | **reported as ignored**, with the help text saying so |
| `--stego` (pipeline CLI) | hard-disabled (`stego=False`) | wired |
| `--cf-token`, `--cf-account` | shadowed by the stored config | the command line wins; the config is the fallback |
| `--platform` | offered `gitlab`; never read | choices are `auto`/`github`; a `_make_farm()` helper dispatches and raises on an unknown platform |
| `--skip-cloud` | never read | suppresses the cloud build farm |
| `--watermark` (pipeline CLI) | named "watermark", used as a build seed AND a licence target | renamed **`--lock-hwid`** (the old spelling still works as an alias) |
| `--build-id` | help claimed "reproducible builds" | help states what it does: seeds the lowering kernel, recorded in the signature sidecar |
| `--opt-level` | only on `scripts/build.py` | also on `pipeline.py obfuscate`, and that subcommand now routes through `build_pipeline` so both CLIs share ONE obfuscation implementation |
| `--tor-proxy` | help said the default was `127.0.0.1:9050` but the default was `None` | the real default is named in the help |

### 3.2 The loader-only flags (C2)

`scripts/build.py` compiles the payload to a **native binary**. It does
not emit the hybrid loader. The loader gates — `--hwid`, `--trial`,
`--kod`, `--hostguard`, `--hwid-lock`, `--driver-check`,
`--split-bootstrap`, `--no-snapshot`, `--no-stdlib-audit`,
`--no-audit-hook-plant`, `--vm-threshold` — are emitted into the
loader, so they cannot apply on that path.

They are **kept** (removing a public flag is a breaking change) but the
help now says `[LOADER ONLY -- ignored by this pipeline]`, and a run
that sets one says so:

```text
[WARN] These flags configure the HYBRID LOADER and are ignored by this native pipeline: trial period
[WARN] Use `python3 -m obfuscator.core.pipeline build` for the loader build path.
```

### 3.3 `--help` must not crash

argparse expands a help string with `%`-formatting, so a single stray
percent sign makes the whole `--help` fail with a `TypeError`. That is
not hypothetical: a help text reading "at least 90% of baseline" broke
`scripts/build.py --help` completely, and with it two tests that assert
a flag is present.

`tests/test_cli_help_renders.py` now runs `--help` for **20 CLIs** and
requires each to exit 0 with non-empty output, plus a static check that
no help string contains a bare `%`.

### 3.4 Naming

* `pipeline.py build --watermark` → **`--lock-hwid`** (the old spelling
  remains an alias). It locks the build to a target HWID; it is not a
  watermark. `scripts/build.py --watermark` is a *different* thing
  (a semantic watermark embedded in the IR) and keeps its name.
* `SecurityGate.threshold_percent` → **`threshold_ratio`**,
  `GateResult.delta_percent` → **`delta_ratio`**. Both hold a ratio
  (0.0–1.0) and are compared as one; only the display multiplied by
  100.
* `version` → one constant in `obfuscator/version.py`, used by both
  CLIs and checked against `config/default.json` by a test.
* The three root-level LLM tools moved to `scripts/evaluation/`:
  `test_deobf_models.py` → `deobf_models.py`, `test_ai_proof.py` →
  `ai_proof.py`, `benchmark_ai_resistance.py` → `ai_resistance.py`.
  They are tools, not tests, and the `test_*.py` names made pytest's
  `python_files` glob treat them as test modules.

## 4. Re-auditing the earlier commits

The previous round's cleanup removed 280 statements across the tree, and
the only evidence it had not broken anything was the test suite. That
is not enough: the "load-bearing removal" class — a statement whose
*call* was the point — is invisible to a test that never exercises that
path. (The `--expire` defect of the previous round is exactly that
class: a module-level import removed, with no test passing `--expire`.)

`scripts/lint/audit_commit_removals.py` makes the review mechanical: it
compares a commit to its parent structurally (AST, f-strings folded) and
isolates the removals that **dropped a call**, because a dropped call is
the only kind of removal that can change behaviour.

| Commit | Statements removed | Dropped a call | Unexplained |
|---|---|---|---|
| `181b151` (first audit round) | 20 | 7 | 0 |
| `1a8c9df` (four-phase round) | 280 | 65 | 0 |

Every dropped call was classified by hand. One was not deliberate and
has been repaired: in `irgen/chaff_circuits.py` the cleanup had changed
the **order** in which IR instructions were emitted, so the generated
artifact differed from the pre-cleanup one. The order is restored and
the output is now verified byte-for-byte identical.

## 6. The four items the brief called out

The brief asked for TLS verification, import-time logging,
`section_split.py` and lint enforcement to be *investigated* before a
solution was chosen. All four were resolved in the previous round; this
round re-verified each and found what the previous round had missed.

### 6.1 TLS verification — verified, and the scope clarified

The emitted key fetch uses a **verified** context: the system trust
store plus an operator CA added via `--tls-ca-bundle`, with
`CERT_REQUIRED` and hostname checking. Verification is never disabled.

This round added no TLS change: the mechanism was already correct, and
the correct response to a correct mechanism is to leave it alone. What
this round did fix is the CLI surface around it — `--platform` no
longer advertises a farm that does not exist, and `--tls-ca-bundle` is
documented where the other flags are.

### 6.2 Import-time logging — verified

Importing `obfuscator.core.utils` creates and truncates no file.
`enable_log_redirect()` is explicit and is called by the entry points.

**But**: the previous round moved the module-level `_console = sys.stdout`
binding into `enable_log_redirect()`, and the *loader CLI* still
referenced `_console` in two places where a **star import cannot reach
it** (underscore-prefixed names are excluded from `import *`). The
result was a `NameError` on every argparse error — a pre-existing bug
since the star import was introduced, not one the previous round
introduced.

It is fixed by looking the name up on the module
(`_nixon_utils._console`), which is also more correct: it reaches the
*current* console handle rather than a stale copy. The runtime
undefined-global checker found it; a static linter cannot, because the
name arrives through a star import.

### 6.3 `section_split.py` — the scope claim was wrong, and is now right

The previous round wired `--section-split` / `--section-count` into the
loader and claimed end-to-end coverage. The gate inside the loader
generator is:

```python
if section_split and _plain and not native_only:
```

so the feature works on the **standard** path and is unavailable in
`--native-only` mode — where there is no fallback payload to split at
all. That is the right design.

What was missing: the help text did not say so, and a build that asked
for the split but could not arm it was **silent**. It now warns:

```text
[WARN] Section split was requested but could not be armed (no fallback payload, or --native-only); the single blob is used instead.
```

And the end-to-end test was strengthened: the pack is a sealed literal
by then and cannot be grepped out of the artifact, so the evidence is
behavioural — the flagged build must differ from the unflagged one, and
the artifact must run.

### 6.4 Lint enforcement — verified, and the gate pinned

`make lint` fails. `ruff.toml` enforces F401, F402, F541, F601, F602,
F811, F821, F841; F403/F405 are ignored **with the reason recorded**,
and the consequence of ignoring them is closed at runtime by
`scripts/lint/check_undefined_globals.py`.

This round found that the gate was not reproducible (C3) and pinned it.

Verified by installing the lock in a clean venv and running the whole suite there |
| **D20** | The pinned ruff could go stale with no signal | AUDIT-2026-10-20 §8.7 | `make lint-upgrade` prints the current pin and the latest release, so bumping it is a reviewed act |
| **D21** | The `z3`-absent path was verified only by stubbing the import | environmental | Verified for real: a venv built from the lock with `z3-solver` uninstalled imports the build CLI, completes a full build, and the artifact runs |
| **D22** | The star-import conversion introduced a **regression**: `utils` binds `np` only when numpy is installed, and the explicit `from .utils import np` made the whole package unimportable without numpy — the 3.10, 3.11, 3.12 and 3.14 builds all failed | the conversion (D13) | The numpy import is lazy again, and the facade is now GENERATED (`scripts/lint/generate_core_facade.py`), which excludes names bound only inside `try/except ImportError`. `make lint` fails if the facade is stale, and a test asserts the package imports with numpy blocked |

### 8.1a The controls that were present but inert

A dedicated pass over the loader's security controls found a class of
defect the previous rounds had not looked for: **a control that is
emitted, documented, and never acts.**  Each is now wired, and each has a
regression test that fails if the wiring is removed
(`tests/test_loader_controls_wired.py`, `tests/test_artifact_tamper.py`).

| # | Control | What it did | Now |
|---|---|---|---|
| **C1** | `--kod` | only wrote a marker; the kill was armed solely by `NIXON_KOD` in the TARGET's environment, so the flag's help ("the artifact terminates when a detection fires") was false | the arming is baked into the loader; the flag alone arms the kill (exit 137) |
| **C2** | the watermark gate | unreachable: no CLI path passed a watermark, so the emitted gate was always `DISABLED` -- while `THREAT_MODEL.md` promoted the row to ENVIRONMENT_VALIDATED | `--watermark MSG` on the loader CLI; the gate is armed and kills on a stripped or edited watermark |
| **C3** | the hostguard | the snippet was emitted but never called, so it checked nothing | the loader binds the host and verifies `exec`/`eval`/`compile` are unpatched before running the payload |
| **C4** | the split-bootstrap (Shamir) key | reconstructed and then ignored: the payload was decrypted with the direct key | the Shamir key IS the key that decrypts the payload |
| **C5** | the plaintext-dump debug aid | shipped in every release artifact (a runtime env switch wrote the decrypted payload to disk) | build-time opt-in only (`--debug-dump-raw`); a normal artifact has no such capability |
| **C6** | the gate ordering | every hybrid-loader gate was emitted AFTER the payload entry point, so a trial-expired artifact ran its payload and only then died | the entry point is emitted last; the gates run first |
| **C7** | the loader's self-integrity | the Merkle root and the HMAC were computed and their verdicts discarded with a bare `pass`; worse, the build filled the anchors *after* the string table had turned them into lookups, so the runtime compared the root against a placeholder and the check never matched | the anchors stay plain literals, the comparison matches, the verdict is terminal, and the check runs BEFORE the state machine |
| **C8** | a failed payload | the importer retried the payload and then swallowed the failure, so a broken or tampered artifact exited 0 -- indistinguishable from a clean run | the importer fails closed, the state machine fails closed, and the loader requires that the payload actually ran |

C8 is the most important: **before this, a tampered artifact looked
exactly like a successful one.**  It ran nothing, printed nothing, and
exited 0.  It now exits 137.

### 8.2 Still open

Six of the nine items that were open before this round are now closed
(the inert controls, §8.1a).  What remains:

1. **The `--opt-level` ladder is not on `pipeline.py build`.** The
   loader build always applies the full transform set, because a loader
   built at level 0 would be a weaker artifact by construction.  This is
   now **documented** (README, loader-CLI section) rather than left as
   an unstated asymmetry, but the flag is genuinely not there.
2. **The 11 loader-only flags still exist on `scripts/build.py`.** They
   are accepted and reported as ignored, not removed, so existing
   command lines keep working.  Removing them is a breaking change that
   should be a deliberate, announced decision.
3. **The lint gate covers a narrow rule set on purpose.** It catches
   undefined names, unused imports and locals, repeated dictionary
   keys, redefinitions, f-strings without placeholders, star imports,
   and -- at runtime -- every global read in the live tree.  It does not
   cover style, complexity, or type errors.
4. **The ruff pin can go stale.** A pinned linter is reproducible but
   not current: new rules stay off until someone bumps the pin.  That is
   the intended trade; `make lint-upgrade` makes the bump a reviewed act.
5. **The outer loader's environment detections are signals, not gates.**
   The anti-sandbox, anti-emulator, anti-debug-frame, geo-fence and
   blockchain-licence checks perturb the loader's hash chain and its
   opaque-predicate seed; they do not terminate the artifact.  That is a
   deliberate design (they make the artifact behave differently per
   environment) and the threat model does not claim them as controls --
   but it is worth stating here, because a detection that does not act
   is exactly the class of defect §8.1a is about.
6. ~~The payload blob is not authenticated.~~ **CLOSED 2026-10-21.**
   The build now computes an HMAC over the payload zip, keyed with the
   inner key the loader already holds, and the loader verifies it
   before extracting anything.  A byte flipped in the payload region
   now exits 137 instead of corrupting the payload silently
   (`tests/test_payload_authentication.py`).

### 8.2c Closed in the final round (2026-10-21, second pass)

The round began with three items reported as uncloseable. All three
are closed. Two of them turned out to be **real defects wearing the
costume of environmental limits**, and the third was a protocol
decision that the code could make for us.

#### The native build path was broken, not environmental

`scripts/build.py` failed in the LLVM stage. It failed *identically on
the unmodified tree*, which is why it had been written off as
environmental — the same reasoning that would have hidden a real bug.
It was not environmental. The `llc` error was
`use of undefined value '%65'`, three files from the cause, and each
fix exposed the next defect.

**The lowering (`llvmgen/lower.py`)**

| # | Defect | Effect |
|---|---|---|
| **N1** | `shr` was not a known opcode. An unrecognised instruction was emitted as a **COMMENT**, so its result stayed undefined while later instructions still used it | `llc` rejected the module: "use of undefined value" |
| **N2** | `gep` was not a known opcode, and the GEP emitter **dropped the indices** | the address was computed from the base alone — a wrong address, not an error |
| **N3** | The IR carries pointers as `i32`; the GEP did not convert the base | `llc` rejected it: "defined with type 'i32' but expected 'ptr'" |
| **N4** | LLVM requires unnamed values to be numbered consecutively; the project's IR numbering has gaps (`%52, %54, %58, ...`) | `llc` rejected it: "instruction expected to be numbered '%335' or greater" |
| **N5** | The comparison opcodes (`lt`/`le`/`gt`/`ge`/`ne`) were not lowered, and the whitespace tokenizer split string constants containing spaces or commas | the branch condition was undefined; string constants were torn apart |
| **N6** | A float constant in an integer operation is not valid LLVM: the operation needs LLVM's `f`-prefixed opcode and a typed constant | `llc` rejected it: "floating point constant invalid for type" |
| **N7** | A call with no arguments was serialised without parentheses, and the callee pattern swallowed the argument list | the call did not parse: "use of undefined value" |
| **N8** | The phi parser expected `%label`; the IR writes `label bb5` | every phi parsed with no incoming values: "PHINode should have one entry for each predecessor" |
| **N9** | The auto-generated `declare` had no parameters, so the declared arity did not match the calls | a call whose signature the runtime does not provide |

**The IR generator (`irgen/compile.py`)**

| # | Defect | Effect |
|---|---|---|
| **N10** | A name the IR could not resolve became the fallback `0`. A constant captured by a nested function (`_nx_M = 4294967295` above `_nx_rl`) was compiled as `x & 0` | a **silent miscompilation** of the ChaCha quarter-round |
| **N11** | `try`/`except` was not a statement the compiler knew, so the whole block was **dropped** | every statement in every try block vanished, and the variables it bound resolved to `0` |
| **N12** | An imported module, a builtin used as a value, a module-level binding, and a list/tuple/dict literal all became `0` | `hashlib.sha256(...)` was compiled as a call on the integer 0 |
| **N13** | The boolean operators (`and`/`or`) left the short-circuit block without a terminator and branched to an empty block; the short-circuit value was inverted | the module did not verify ("expected instruction opcode"), and the result was the wrong value |
| **N14** | A function returning a boolean expression returned `i1` from an `i32` function | the return type did not match the signature |
| **N15** | The f-string concatenation put a TYPE in the operand list instead of a value | the operand serialised as the text `ptr`, and the lowering read it as a value named `ptr` |
| **N23** | `None` was a pointer-typed `null`, stored into the IR's i32 slots | `llc` rejected it: "null must be a pointer type" — `None` is the integer 0 in this model |

**The optimizer (`irgen/optimize.py`)**

| # | Defect | Effect |
|---|---|---|
| **N16** | The dead-code pass read a phi's operands as plain values, but they are `(value, label)` **pairs** | the instruction that produced the value was deleted, leaving the phi pointing at nothing |
| **N17** | The store-to-load forwarding had the same blind spot | a phi could keep a reference to a replaced value |

**The OLLVM passes (`llvmgen/passes.py`)**

| # | Defect | Effect |
|---|---|---|
| **N18** | A pass that adds a branch gives the target block a new predecessor, and LLVM requires one phi entry per predecessor | the module did not verify |
| **N19** | The new entry copied the original predecessor's value, which does not dominate the block | "Instruction does not dominate all uses" — and the pass was **flaky**: it failed on roughly half the runs |
| **N20** | Flattening a function with phis breaks SSA | the module did not verify; such a function is now left unflattened |

**The build pipeline**

| # | Defect | Effect |
|---|---|---|
| **N21** | `scripts/phases/phase04_encrypt.py` invoked `encrypt/encrypt.py` as a **script**, but that file uses a relative import (`from . import aes`) | the encryption stage could never work; it now runs the package CLI (`python -m encrypt`) |
| **N22** | The environment snapshot called `platform.processor()` / `platform.machine()`, each of which runs an untimed `uname` subprocess | the build could hang indefinitely (it blocked for five minutes under load); it now reads `os.uname()` |

**The fix was not only in the lowering.** `llvmgen/lower.py` now
**fails loudly** on an instruction it does not recognise, instead of
emitting a comment: a dropped instruction is a silent
miscompilation, and the error message pointed three files away from
the cause. The IR generator now resolves constants from the enclosing
scope (a closure) and from the module level, gives an imported module
an opaque handle, compiles a `try` body, promotes an operation to
floating point when either operand is a float, and — in **strict
mode** (the default for `python -m irgen` and the native build) —
**fails** on a name the IR cannot represent rather than shipping a
zero.

**Verification:** `scripts/build.py` completes the native path on this
host and produces a valid ELF relocatable object (`build/program.o`,
`build/encrypted.o`), with the OLLVM passes applied.
`tests/test_native_lowering.py` covers each defect above, including
end-to-end `llc` runs of the plain and the obfuscated module.

#### The shared signing key and the unsigned farm runners

Both were recorded as protocol decisions in ADR-0005. The code can
make the decision for us, because the property that mattered —
*a verifier must not be able to mint an artifact it will later
accept* — is a property of the KEY, not of the deployment.

The farm now holds an **Ed25519 private key** and signs what it
stages; the operator pins the farm's **public** key:

| | Before | After |
|---|---|---|
| Signing key | one shared HMAC key, held by every farm **and every verifier** | per-farm Ed25519 key pair; the farm holds the private half, the operator the public half |
| What a verifier can do | verify **and forge** | verify only |
| Farm identity | a claimed string inside the signed metadata | the public key itself: a sidecar names the key that signed it (`key_id`) |
| Key rotation | rotate the shared key, which invalidates every farm at once | rotate one farm's pair; the pinned public key map is updated per farm |
| Unsigned farm-runner binaries | by design — the runner had no key | the runner signs with the farm's key; a runner without it produces no valid sidecar, and an unpinned signer is rejected |

The new sidecar shape is `ed25519-binding-v1`:
`{"algo", "sig" (base64), "key_id", "metadata", "file"}`, over the same
signed material as the HMAC path (`file bytes + 0x00 + canonical
(metadata)`), so `farm`, `issued_at` and `expires_at` stay bound in.

**Compatibility:** the HMAC path is untouched and still verifies. The
Ed25519 path is *preferred* whenever a private key is configured
(`NIXON_ARTIFACT_ED25519_KEY`); the operator pins with
`NIXON_ARTIFACT_ED25519_PUBKEY` (one key) or
`NIXON_ARTIFACT_ED25519_KEYS` (a JSON map of farm id → hex public
key). The download gate enforces Ed25519 sidecars with the pinned
public keys, and refuses a sidecar signed by a key it does not pin.

**Verification:** `tests/test_artifact_signing_ed25519.py` — including
the property that made this worth doing: a sidecar forged with a
different private key **does not verify** against the pinned public
key.

### 8.2d Closed in the last round (2026-10-21, third pass)

Three findings, all of them found by asking the questions the earlier
rounds did not ask.

**The artifact's self-check could be edited away.** The loader checks
its own bytes against a Merkle root and an HMAC. The lines it hashes
exclude the two that hold the expected values — identified by a
**marker string**. The marker's own line was excluded from the hash as
well, so editing the marker was invisible to the check. And an
exception inside the check was logged and ignored, so breaking the
check's own code (a `NameError`, a damaged Merkle helper) turned the
control off: the artifact carried on, ran the payload and **exited 0**.

A scan of ~6900 byte positions across three builds found **12 offsets
that were not caught** — every one of them inside the check's own
code. The fix: the excluded lines are identified by their **values**
(the check's code is then hashed like everything else), a check that
cannot run **fails the artifact**, and the build verifies that the
runtime's filter selects the same lines the build's did (otherwise
every run of the artifact would die — a false positive the build now
catches instead of shipping).

`tests/test_payload_authentication.py::test_tampering_with_the_self_check_is_detected`
is the regression: it flips bytes in the check's own code and requires
each to be caught. Verified to **fail on the old code** and pass on the
new.

**The artifact bundler extracted with no confinement.**
`scripts/artifacts/bundler.py:verify_bundle` unpacked a bundle with a
bare `extractall` — no path check at all. It is the same ZipSlip family
the build-farm paths were fixed for; the test missed it because the
test scanned **one module**. The confinement now lives in one shared
module (`obfuscator/core/archive_safety.py`, standard library only, no
import side effects) and the test scans the **whole tree**.

**The suite had warnings, and one of them was a behaviour change.**
Every warning is now gone:

| Warning | Where | Why it mattered |
|---|---|---|
| `tarfile` extraction without `filter="data"` | `scripts/artifacts/bundler.py`, `scripts/verification_bundle/bundler.py` | Python 3.14 changes the default — this is a behaviour change, not noise |
| `datetime.utcnow()` | `tests/test_coverage.py` | deprecated |
| `pkg_resources` | `scripts/reproducibility/environment.py` | deprecated API; `importlib.metadata` is used now |
| `fork()` in a multi-threaded process | `scripts/distributed/*` (8 spawn sites), `scripts/gpu/hybrid_protection.py` | deprecated since 3.12, may deadlock in the child, and 3.14 changes the default — the distributed modules now spawn with "spawn" explicitly |

### 8.2e Nineteen tests that never ran

The suite reported 23 skips. Four were deliberate. **Nineteen were
not**: they need a compiled artefact — the C shared libraries, the
Rust relay binary, the microjit shared object — and each skips
itself when the artefact is absent.

CI scheduled `make core` **after** `pytest`, so CI skipped all
nineteen too: the encrypt path and the Rust relay were never
exercised there. A skipped test proves nothing, and a test that
skips because a build step did not run is a test the CI is not
really running.

The artefacts are now built **before** the tests, and
`NIXON_REQUIRE_ARTEFACTS=1` (set in CI) makes a missing artefact a
**failed build** rather than a quiet skip —
`tests/test_artefact_gate.py`. Verified here: with the artefacts
present, 4375 tests pass and the skips fall from 23 to 4; the gate
fails as it should when an artefact is removed.

The microjit skip message also gave a build command that did not
work (it omitted two source files, so the shared object had an
undefined symbol). It now points at `make microjit-so`.

### 8.2f The FHE/ORAM C backend could never load

Asked while checking the artefact-dependent skips: "isn't
`test_encrypt` something we don't need?" — the answer was no, but
asking it found a real gap.

The loader loads `nixon_core.so` from the directory of **its own
file** — the artifact's directory. Nothing ever built it there, so
the loader always took its pure-Python fallback, where
`encrypt_batch`/`dec_batch` are **no-ops** (`res = value_array[:]`):
the FHE bootstrap verified nothing, in every build, while the build
reported FHE and ORAM as enabled.

The library is now built **next to the artifact** (one helper,
`obfuscator/core/c_core_build.py`, used by both build paths), and the
build reports which of the loader's symbols the library actually
exports. It reports this:

```
[+] C core built: .../dist/nixon_core.so
[!] The C core does NOT export FHE_new, FHE_encrypt_batch,
    FHE_dec_batch, ORAM_new, ORAM_access -- the loader will use its
    pure-Python fallback, where the FHE encrypt/decrypt are no-ops.
    The FHE/ORAM bootstrap is a self-test, not a protection.
```

**What is and is not true:** the FHE/ORAM C backend is **not
implemented** — `FHE_*` and `ORAM_*` exist nowhere in `native/`. The
bootstrap is a *self-test* of the crypto pipeline, not a protection
(the payload's real protection is the XOR plus the HMAC), so nothing
is unprotected by this; but the build must not imply otherwise, and
now it does not. `tests/test_c_core_wiring.py` records the fact and
fails if the symbols ever appear without the warning being updated.

On the skips themselves, the honest answer:

| Tests | Verdict |
|---|---|
| `test_encrypt.py` (9) | **needed** — the build runs that path (`scripts/build.py`, `phase_encrypt_binary` → `build/encrypted.o`), and the nine that were skipping are the ones that parse the **real relay binary**, not a synthetic ELF |
| `test_rust_relay.py` (3) | **needed but thin** — the only tests that execute the shipped binary's CLI; the e2e check runs the *artifact*, not the relay |
| `test_core.py` (3), `test_wb_rounds.py` (2) | the whitebox C implementation is real and shipped in `build/`, but the loader uses its own pure-Python whitebox, so the C one is not on the artifact's path |
| `test_microjit.py` (3 of 33) | **needed** — the microjit object *is* compiled into the build, so the C code under test ships |

### 8.4 Environmental limitations

1. **The suite is run in chunks.** The host has roughly 1 GB free of
   7.6 GB and the harness cut off long single runs; the totals are the
   sum of the chunks. The host's memory state is not a property of the
   code.
2. **The cloud build farm was not exercised against GitHub.** The
   fixes to it (timeouts, deadline, rate-limit backoff) are covered by
   tests that stub the transport; the real API, real rate limits and
   the real Tor path are unverified here. The farm is opt-in.
3. **The cross-compiled and Windows/ARM64 artifacts were not built.**
   `native/stub_win.cpp`, the MinGW cross path and the ARM64 relay
   target need toolchains this host does not have; the Rust crates are
   covered by `cargo test` on the native target only.
4. **The `z3`-absent path is verified for real**: a venv built from
   the hash-pinned lock with `z3-solver` uninstalled imports the build
   CLI, completes a full build, and the artifact runs.
5. **~~The native binary path cannot be built on this host.~~ CLOSED
   (2026-10-21).** This was recorded as environmental because the
   failure was identical on the unmodified tree. It was not
   environmental: it was **seven real defects** in the IR → LLVM path,
   each one hiding the next. The native build now completes on this
   host and produces a valid ELF object. See §8.2c.
6. **The cloud build farm is not exercised against GitHub.** The
   timeouts, the deadline and the rate-limit backoff are covered by
   tests that stub the transport; the real API, real rate limits and
   the real Tor path are unverified here.  The farm is opt-in.
